# ADR(決めたことの記録)

Rust への置き換えで決めたことを、1 件 1 ファイルで残す。人が後から読んで、何をなぜ決めたかがわかるように書く(`docs/rust-migration/plan.md` の「作業の記録」)。

## ファイルの名前

`docs/rust-migration/adr/NNNN-<題>.md`

- `NNNN` は、その決定をした作業の Issue の番号を、0 で埋めて 4 桁にしたもの(Issue #107 なら `0107`)。Issue のない作業(段階の関門など)は、ADR を書く前に、その作業の Issue(ラベル `rust-migration`)を作り、その番号を使う。coordinator は 1 つの Issue を 1 つの thread にだけ渡すので、並行する thread が同じ番号を使うことはない
- `<題>` は英小文字とハイフンで書く(例: `0107-crate-split.md`)。1 つの Issue で 2 つ以上を決めたときは、同じ番号で題を変える(`0107-crate-split.md` と `0107-glossary-scope.md`)
- ほかの文書や ADR から ADR を指すときは、番号だけでなく、拡張子を除いたファイル名で書く(`0107-crate-split`)

番号は決めた順にならない(Issue は先に作られ、着手は後になるため)。決めた順は、各 ADR の「決めた日」で読む。一覧のファイルは置かない(並行する thread が同じファイルを書き換えて衝突するため)。このフォルダーのファイルの一覧が、ADR の一覧になる。

## 書くこと

```markdown
# <決めたこと>

- 状態: 採用(または 不採用)
- 決めた日: YYYY-MM-DD
- Issue: #<番号>
- 置き換える: <前の ADR のファイル名>(前の決定を変えるときだけ)

## 状況
何を決める必要があったか。前提と制約。もとにした報告(`docs/rust-migration/architecture/` など)があれば、そのパス。

## 決定
何をどうすると決めたか。

## 検討した代わり
選ばなかった案と、選ばなかった理由。

## 依存
追加する crate や外部の道具(Zig など)ごとに、名前、版、入手元、ライセンス、保守の状況、`build.rs` が実行すること。追加しないときは「なし」。

## 結果
この決定で、何ができるようになり、何ができなくなるか。あとの段階の作業が従うこと。

## 確かめたこと
試作やテストで実際に確かめたこと: 実行したコマンド、使った PC と OS、版、結果。
```

- 状態は、決めたことを使うなら「採用」、検討して使わないと決めたこと(例: 試作で使えないとわかったライブラリ)を記録するなら「不採用」
- 試作の ADR は、通った場合も通らなかった場合も書く。通らなかった場合は、代わりに選んだものと、その代わりで確かめたことを書く
- 前の決定を変えるときは、新しい ADR を書き、「置き換える」に前の ADR のファイル名を書く。前の ADR は書き換えない(2 つの thread が同じ ADR を置き換えるときに、同じ行を書き換えて衝突しないように)。ある ADR が置き換えられたかは、`grep -lF '置き換える: <ファイル名>' docs/rust-migration/adr/*.md` で調べる
- PR の番号は、ADR には書かない(コミットの時点ではわからないため)。どの PR で入ったかは `git log` で調べる
