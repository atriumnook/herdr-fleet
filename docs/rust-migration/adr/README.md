# ADR(決めたことの記録)

Rust への置き換えで決めたことを、1 件 1 ファイルで残す。人が後から読んで、何をなぜ決めたかがわかるように書く(`docs/rust-migration/plan.md` の「作業の記録」)。

## ファイルの名前

`docs/rust-migration/adr/NNNN-<題>.md`

- `NNNN` は、その決定をした作業の Issue の番号を、0 で埋めて 4 桁にしたもの(Issue #107 なら `0107`)。Issue のない作業(段階の関門など)は、その PR の番号を使う。GitHub では Issue と PR の番号は 1 つの連番なので、並行する thread が同じ番号を選ぶことはない
- 1 つの Issue で 2 つ以上を決めたときは、`0107-a-<題>.md`、`0107-b-<題>.md` のように番号のあとに英小文字を足す
- `<題>` は英小文字とハイフンで書く(例: `0107-crate-split.md`)

番号は連続しない。一覧のファイルは置かない(並行する thread が同じファイルを書き換えて衝突するため)。このフォルダーのファイルの一覧が、ADR の一覧になる。

## 書くこと

```markdown
# NNNN: <決めたこと>

- 状態: 採用(または「ADR MMMM に置き換えられた」)
- Issue: #<番号>、PR: #<番号>

## 状況
何を決める必要があったか。前提と制約。

## 決定
何をどうすると決めたか。

## 検討した代わり
選ばなかった案と、選ばなかった理由。

## 結果
この決定で、何ができるようになり、何ができなくなるか。あとの段階の作業が従うこと。

## 確かめたこと
試作やテストで実際に確かめたこと: 実行したコマンド、使った PC と OS、版、結果。
```

- crate を追加するときは、ライセンス、保守の状況、`build.rs` が実行することを「決定」か「確かめたこと」に書く(計画の「守ること」)
- 試作の ADR は、通った場合も通らなかった場合も書く。通らなかった場合は、代わりに選んだものと、その代わりで確かめたことを書く
- 前の決定を変えるときは、新しい ADR を書き、古い ADR の「状態」を「ADR MMMM に置き換えられた」に変える。古い ADR の本文は書き換えない
