段階 2 の解析の crate(screen と transcript)に移す TypeScript のコードの調査

2026-11-08。Issue #192。対象は、計画の段階 2 で Rust の herdr-fleet-screen と herdr-fleet-transcript に移すコード: 承認画面の解析(server/prompt.ts、1,471 行)、adapter の画面の判定(server/fleet/adapters.ts の画面を読む関数)、会話ログの解析(server/conversation.ts の解析とページング、server/codex.ts の解析、server/codex-images.ts、server/pi-tree.ts、server/opencode-messages.ts、server/opencode-session.ts、server/transcript-records.ts、server/conversation-metadata.ts、server/skill-activity.ts、server/tool-output.ts、server/conversation-errors.ts)。手順は improve-codebase-architecture、語は codebase-design(module、interface、depth、seam、adapter、leverage、locality)と docs/rust-migration/GLOSSARY.md に従う。

調べ方: 範囲は計画が決めているので、変更の多いファイルから選ぶ手順は使わなかった。2026-10-01 以降のコミットでの変更の回数は、adapters.ts 31、conversation.ts 20、prompt.ts 15、codex.ts 10、opencode-session.ts 8 で、adapters.ts の変更の多くは起動の引数と OpenCode の設定(段階 3 の orchestrator の側)だった。subagent 1 つがファイルの構成と呼び出しの関係を調べ、lead が transcriptStream、opensTurn、parseTurns、liveTurns、parsePrompt、answerKeys を読んだ。

Problem: ページングの処理(カーソル、history_id、version、窓の読み取り、cache)は 4 つの source で共通なのに、source の違いが source === "codex-transcript" などの分岐として 6 つ以上の関数に散っていて、1 つの source を移すには共通の処理のファイルを書き換えることになる。

Solution: 共通のページングを Transcripts の値の中に閉じ、source の違い(ターンの始まりの判定、ターンの解析、読む範囲の並び(Codex の連なり、pi の枝)、/clear などの履歴の境目、実行中のターンの読み方)を source ごとの module が実装する 1 つの seam で受ける。

  • source を足すと module が 1 つ増えるだけ
  • source ごとの作業が並行できる
  • ページングは 1 か所で試す
  • adapter が 4 つで本物の seam

Problem: 答えのキーを作るのに要る値(responder、メニューの行、選択中の行、自由入力の行)を、公開のカードから WeakMap で引いている。カードを複写すると答えられなくなり(InvalidAnswer("The prompt was not produced by parseInteractivePrompt."))、その決まりは型に表れない。

Solution: 解析は、公開のカード(protocol の型)と答え方を持つ 1 つの値を返し、答えのキーはその値から作る。

  • WeakMap が消える
  • 答えられない状態を型で防ぐ
  • corpus の answers が同じ値を通る

  • 系統ごとの作業が並行できる
  • 行の読み取りは 1 か所

Problem: TypeScript の port は Promise を返す。transcript の crate は tokio に依存できない(ADR 0107-crate-split)ので、Rust で同じ形にすると、corpus の runner が非同期の値を動かす手段を別に持つことになる。

Solution: port は adapter が 2 つ(core の CLI、corpus の記録した応答)ある本物の seam なので残す。同期か非同期かは ADR 0192-phase-2-split で決める。

  • adapter が 2 つで本物の seam
  • source のほかの作業と独立

一番の推奨: 1. transcript のページングの deep module と source ごとの seam

段階 2 の作業を並行できるかは、共通の処理(transcript のページング、承認画面の行の読み取り)を最初の Issue が書き終え、あとの Issue が source や系統ごとの module だけを書けるかで決まる。候補 1 はその seam が最も多くの分岐(6 つ以上の関数)にまたがるので最初に決める。候補 3 と 5 は同じ考えを承認画面と共通の記録の読み取りに当てたもので、ADR 0192-phase-2-split は 1、2、3、4、5 を Issue の分け方にし、6 は seam を残したまま port の形だけを決めた。
