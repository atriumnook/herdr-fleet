# herdr-fleet

[Herdr](https://herdr.dev/) 上で動く複数のコーディングエージェント(pi / Claude Code / Codex / Cursor / Antigravity)を、ブラウザから見て操作するための個人用ツール。

現時点の中身は、[herdr-web-ui](https://github.com/devswha/herdr-web-ui) v0.3.45 から派生した Web UI です。上流の履歴は取り込んでおらず、起点のコミットは [NOTICE](NOTICE) に記録しています。上流の変更は自動では取り込まず、差分を読んでから手で移します。

## 上流から外したもの

外部へ送信するもの、他人のコードを取得して実行するもの、認証を弱めるものを中心に削除しました。

| 機能 | 外した理由 |
|---|---|
| 自己更新(updater / supervisor)、Herdr 本体の更新 | git タグからの clone・ビルド・切り替えを自動で行う |
| リモート PC(SSH)、bridge の登録 | GitHub Releases のバンドルを配布して実行し、リモートの `authorized_keys` に追記する |
| 使用量メータ | 各サービスの OAuth トークンを読んで、非公開のエンドポイントを呼ぶ |
| 音声入力 | 音声と API キーを OpenAI に送る |
| Herdr プラグイン定義、install スクリプト | ビルドと起動のコマンドが自動で実行される |
| 韓国語・中国語の翻訳、配布サイト、動画素材 | 使わない |

## アクセス制御

- token(`HERDR_FLEET_TOKEN`)も紐付け済みの端末もないリクエストは、このPC上からループバックの Host で来たものだけを通す。DNS rebinding で来たリクエスト(送信元はループバックでも Host が外部名)は拒否する
- 他の端末は、PC 上の 設定 → デバイス で発行したペアリングコードで紐付ける
- ファイルの表示は、ペインの作業フォルダーと一時フォルダー(`os.tmpdir()`)の配下に限る。シンボリックリンクは解決してから判定する
- push 通知の宛先は、ブラウザベンダーの push サービス(FCM / Mozilla / Apple / WNS)に限る
- `@` 補完のための `git ls-files` は、`core.fsmonitor` を無効にして実行する

## 必要なもの

- [Herdr](https://herdr.dev/)
- [Bun](https://bun.sh/)
- Node.js(ターミナル表示の PTY sidecar に使う)

## 起動

```bash
bun install --ignore-scripts
bun run start
```

既定では `http://127.0.0.1:7317` で待ち受けます。

| 環境変数 | 意味 |
|---|---|
| `HOST` / `PORT` | 待ち受けアドレス(既定 `127.0.0.1` / `7317`) |
| `HERDR_FLEET_TOKEN` | アクセストークン。設定すると、ループバックからのアクセスにも token か紐付け済み端末が必要になる |
| `HERDR_FLEET_STATE_DIR` | 状態(紐付けた端末、push の鍵と購読)の保存先。既定は `~/.config/herdr-fleet` |
| `HERDR_FLEET_HERDR_BIN` | 使う `herdr` 実行ファイル |
| `HERDR_FLEET_TAILSCALE_OWNER` | Tailscale 経由で入れる所有者のログイン名 |
| `HERDR_FLEET_PUSH_SUBJECT` | push 通知の VAPID subject |

## 使用量と振り分け

fleet はエージェントを起動する前に、その CLI のサブスクの使用量を確かめます。どちらかの枠(5 時間・週・月)の使用率が `maxUsedPercent`(既定 90)以上なら、その候補を飛ばします。rate limit のエラーで止まった CLI もクールダウンに入れて飛ばします。クールダウンは、エラー文に解除時刻があればその時刻まで、なければ `rateLimitCooldownMinutes`(既定 60 分)の間続きます。

使用量は、各 CLI 自身に問い合わせて取得します。認証情報のファイルは読みません。

| CLI | 取得方法 |
|---|---|
| Codex | `codex app-server` の `account/rateLimits/read` |
| Claude Code | `claude -p /usage`(モデルを呼ばず、セッションも保存しない)。全モデル共通の 5 時間枠と週枠を使う |
| Antigravity | `agy -p /usage`(モデルを呼ばないので、トークンを消費しない)。Gemini とそれ以外のモデル群で別々に数える |
| Cursor | ターンが終わったペインで `/usage` を開いて画面から読む。前回の値から 10 分以上たったときだけ読む |
| pi | 取得しない。エラー検知によるクールダウンだけで扱う |

役割の `fallbackModels` には、同じ CLI のモデルのほかに、`<agent>:<model>` の形で別の CLI を並べられます(例: `["codex:gpt-6", "claude:claude-sonnet-5-5"]`)。fleet は、最初に使える候補で起動します。どの候補も使えなければ、理由を並べて起動を断ります。`fleet spawn --model codex:gpt-6` のように、呼び出し側から別の CLI を指定することもできます。

Web UI では、ヘッダーの Fleet ボタン(対応が必要な run の数を表示)から Fleet 画面を開けます。対応が必要なもの、失敗したもの、作業中のもの、完了したものの順に run を並べ、使用量とクールダウンを見出しの横に表示します。run を選ぶと、問いかけ、振り分けの経緯、結果を見られます。

```bash
fleet usage             # 使用量とクールダウンの一覧(古い値は取り直す。--refresh ですべて取り直す)
fleet usage clear agy   # クールダウンを解除する(アカウント名、CLI 名、または省略ですべて)
```

## スレッド

スレッドは、プロジェクトの作業の 1 単位です。専用のワークスペースを持ち、git リポジトリでは専用の worktree(ブランチ `fleet/<id>`)で作業します。worktree はリポジトリの中の `.herdr-fleet/worktrees/<id>` に作ります。リポジトリを信頼済みの CLI(claude、codex、cursor で確認)は、その下のフォルダについて改めて信頼を聞かないためです。元のチェックアウトの `git status` に出ないよう、リポジトリの `.git/info/exclude` に 1 行足します(`.gitignore` は変えません)。担当(役割 `lead`)は自分でも手を動かし、他のエージェントに渡した作業は、そのワークスペースのタブに 1 人ずつ開きます。担当は、受け入れ条件を結果ファイルの隣の `contract.md` に書き、それと照らし合わせて終わります。

```bash
fleet thread --title "通知の重複を直す" --task "リトライで通知が 2 回届く。再現してから直す。"
```

新しい worktree には依存が入っていないので、担当が起動する前に走らせる準備のコマンドを、リポジトリごとに `~/.config/herdr-fleet/fleet.json` に書けます。リポジトリ側の `.herdr-fleet/fleet.json` に書いたものは使いません(リポジトリが、fleet に実行させるコマンドを決められないようにするため)。

```json
{ "projects": { "/home/me/git/app": { "setup": "bun install --ignore-scripts" } } }
```

## まとめ役

まとめ役(役割 `coordinator`)は、プロジェクトに 1 人の、使う人が話しかける相手です。git リポジトリ(リポジトリでなければそのフォルダ)ごとに 1 人で、元のチェックアウトにある専用のワークスペース「<リポジトリ名> · fleet」で動きます。コードを読んで答え、手を動かす依頼はスレッドに分けて起こします。自分ではファイルを編集しません。そのため、編集の道具を外して起動できる CLI だけが、まとめ役を担います。今は claude だけです。codex は、`--approve-for-me` が読み取り専用のサンドボックスを上書きするため、外しています。まとめ役はスレッドの終わりを待ちません。

担当が迷ったときは、迷いの種類で行き先が決まります。

- どう作るか(設計、方式、既存のコードとの整合): 担当が技術判断役(役割 `architect`)に聞きます。技術判断役はコードを根拠に答え、ファイルは編集しません。何を作るかは決めず、そういう問いだとわかったら BLOCKED で返します
- 何を作るか・なぜ作るか(要件、範囲、優先度): 取り消せる仮定で先へ進めるなら、担当は最も妥当な仮定を置いて進み、HANDOFF の Assumptions に書きます。取り消しにくいときだけ、選択肢・推奨・技術判断役の見立てを付けた BLOCKED の HANDOFF で尋ねます
- 実行してよいか: 各 CLI の承認画面で、使う人に直接聞きます

担当が BLOCKED でターンを終えると、fleet がその HANDOFF を問いとしてスレッドの run に残します。まとめ役の手が空いたら(fleet が渡したターンが終わり、herdr も作業中と言っておらず、入力欄に使う人の打ちかけの文がないとき)、溜まった問いを `[fleet]` で始まる 1 通にまとめて渡します。打ちかけの文があれば、少し待ってからもう一度試します(今は claude の入力欄を見分けます)。まとめ役は、使う人がこの会話で既に決めたことならそれを担当に `fleet send` で伝え、そうでなければ選択肢と推奨を付けて使う人に聞きます。まとめ役が動いていない間の問いは、そのプロジェクトで次に起動したまとめ役に渡します。問い以外(PASS、ISSUES、失敗、画面での承認待ち)はまとめ役を起こさず、スレッドの一覧と push 通知で使う人に届きます。承認の画面には、まとめ役は答えません。

`fleet threads` は、スレッドごとに状態を返します。Working(担当が作業中)、Waiting on you(担当の問いか承認の画面で、使う人を待っている)、Ready for review(PASS で終わった)、Idle(それ以外で終わった)、Failed(失敗した)、Ended(ペインが閉じた)のいずれかです。

```bash
fleet project --task "通知の重複と README の古い記述を直して"   # まとめ役がいなければ起動し、いればこの依頼を渡す
fleet threads                                                     # このプロジェクトのスレッド: 状態、ブランチ、HANDOFF の 1 行目、受け入れ条件
```

役割の定義に `edits: false` と書くと、その役割はファイルを編集しない役割になります(claude では Edit / Write / NotebookEdit を外して起動します)。編集を止められない CLI の候補は、理由を記録して飛ばします。シェルのコマンドは使えるので、シェルでの書き込みは指示文と各 CLI の auto mode で抑えます。

## 開発

```bash
bun run typecheck
bun run test:unit          # Herdr を使わないテスト
bun run test:integration   # Herdr を使うテスト
bun run build
```

- `bun test` を実行すると、まず `scripts/test-herdr.ts` が preload され、テスト専用の Herdr セッション `herdr-fleet-test` を起動する。このセッションはテスト後も常駐する。止めるときは `herdr --session herdr-fleet-test server stop`
- `bun run test:unit` は `HERDR_TEST_MODE=unit` を付けて preload を止めるが、`HERDR_*` 環境変数はそのまま引き継ぐ。Herdr のペイン内で実行すると普段使いのセッションに接続しうるので、`HERDR_*` を外して実行する

## 目指す姿

複数のサブスク(Claude Code / Codex / Cursor / Antigravity / pi)を、一つのチームとして働かせます。使う人は Web UI で「これをやって」と頼むだけで済み、役割の割り振りと、使用量に応じた CLI の選び分けは裏で行われます。今はまだ、起動に `fleet` CLI を打ち、設定はファイルを直接書く必要があります。次の形に移していきます。

- **窓口は Web UI。** 頼む、設定する、経過を見る、呼ばれたら判断する、を画面で完結させる。`fleet` CLI と `fleet.json` は、エージェント同士と内部で使う手段で、使う人が知っている必要はない
- **話しかける相手はプロジェクトに 1 つの会話。** その会話のまとめ役が、頼まれたことをスレッドに分けて起こし、進み具合を追い、質問に答え、結果を報告する
- **スレッドは専用のブランチと会話を持つ。** 1 つのスレッドに 1 つのワークスペースと、git リポジトリなら 1 つの worktree。スレッドの担当は自分でも手を動かし、並べて進められる部分、広い調査、別の CLI の目が要るレビューだけを他のエージェントに渡す。渡したエージェントはそのワークスペースのタブに 1 人ずつ開き、表示中の画面は奪わない。渡した結果はファイルで受け取り、会話には要点だけを入れる
- **CLI は使用量で選ぶ。** スレッドの担当と渡す先は、役割ごとの候補の順番と使用量で CLI を選ぶ。まとめ役は、編集を止められる CLI に限る(今は claude だけ)。レビューは、書いた CLI とは別の CLI に回す
- **スレッドの一生を状態で示す。** 作業中、待っている、結果を見てほしい(マージする・PR を作る・捨てるを選ぶ)、取り込み中、閉じた。エージェント 1 人の状態(Working / Needs you / Done / Idle / Failed)とは別に数える
- **質問はまず持ち主へ。** スレッドの担当が迷ったらまとめ役に聞き、まとめ役が決められないときだけ使う人に聞く。コマンドの承認は使う人だけが答え、fleet が代わりに答えることはしない。呼ぶときは画面と push 通知で知らせる
- **スレッドを閉じると片付ける。** ワークスペースと worktree を消す(マージしていない変更があれば先に確かめる)。準備のコマンド(依存のインストールなど)はプロジェクトごとに設定する
- **設定は画面から。** 役割ごとの CLI とモデルの候補の順番、使用量の上限を設定画面で変える。保存先は今の `fleet.json`
- **ペインの会話から頼む経路は追加の入口。** pi や Claude Code の会話の中から頼めるようにするのは最後に回す。その呼び方が herdr-fleet の作りを縛ることはない
